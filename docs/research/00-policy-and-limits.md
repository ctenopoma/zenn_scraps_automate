# 00. Zennの方針・規約・投稿上限（前提条件）

調査日: 2026-10-01

## AIコンテンツ方針（2026-03-10）

出典: https://info.zenn.dev/2026-03-10-ai-contents-guideline

- 記事・本について
  - ユーザーごとに「期間あたりの投稿上限数」がある。上限は複数の指標で決まるため、ユーザーによって異なる。
  - 運営は「ボットを用いてアカウントを自動運用する方」を名指しで懸念している。
  - 違反時はアカウント凍結を含む措置がありうる。
- スクラップについて（原文）
  > スクラップに関しては「学習ログなどを気軽に残せるメモ」という位置付けであることから、AIの出力を次々に投稿するような使い方をしていただくことができます。なお、記事や本に比べて大幅に緩いものの、スクラップにおいても1日あたりの上限が存在することはご了承ください。
- 結論: **スクラップにも上限はある（数値は非公開）**。

## 利用規約

出典: https://zenn.dev/terms （2025-06-05改定）

自動化に関係しそうな条項は次のとおり。

| 条項 | 内容 |
|---|---|
| 第4条1項3号 | 運営者のサーバーまたはネットワークの機能を破壊したり、妨害したりする行為 |
| 第4条1項4号 | 本サービスの運営を妨害する行為、または妨害するおそれのある行為 |
| 第4条1項11号 | スパムとみなされる行為（機械により自動生成された文章の投稿や同一内容の文章を繰り返し投稿する行為など） |
| 第3条 | 認証情報の管理責任。第三者への譲渡・貸与の禁止 |
| 第16条2項 | 運営は事前の催告なしに公開停止・利用停止などを行える |
| 第18条 | 運営は通知なしに仕様変更・機能停止を行える |

- スクレイピングや非公式APIの利用を名指しで禁止する条項はない。
- ただし内部APIは第18条により、予告なく変わりうる。

## 投稿上限について分かっていること

- スクラップの日次上限: **数値・エラー文言・HTTPステータスとも未確認**。
- Public API（02参照）には `429 rate_limit_exceeded` がある（zenn-cli のテストのモックで確認）。
- zenn-cli のヘルプには一時期、具体的な数値が書かれていたが、2026-09-28 のコミット `000f200`（"omit Public API rate limit thresholds"）で削除された。**数値は変わる前提で設計する**。
  - 「IPアドレスごとに毎分60リクエスト」
  - 画像は「通常ユーザーは直近24時間に50ファイル・合計50MiB」
- 記事の上限に当たったときの文言（参考）:
  - 「次の記事は一定時間以内の投稿数の上限に達したため…」（https://zenn.dev/kiitosu/scraps/82de0b7edd8618 ）
  - 運営は、問い合わせても上限の基準を開示しない。

## 設計上の帰結

1. **自前のレート制限**（例: 1日N件）を入れる。上限エラーが返ったら再試行せずに止める。
2. **冪等性**: 同じ内容を二度投稿しない。投稿済みのものは hash と slug で管理する。規約11号の「同一内容の繰り返し投稿」を避けるため。
3. **人がトリガーする**: 完全な無人運用（ボット運用）は、運営が名指しで懸念している。そのため、人がレビューして実行指示を出す形にする。
4. **テストは限定公開（unlisted）で行う**: 限定公開は作成時にしか選べず、公開済みのスクラップを後から限定公開にはできない（https://info.zenn.dev/2025-03-05-release-unlisted-scrap ）。
