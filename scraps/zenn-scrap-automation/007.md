## 比較と暫定方針

| 方式 | 正当性 | トークン | 認証情報リスク | 壊れやすさ |
|---|---|---|---|---|
| **公式 Public API** | ◎ | ほぼ0 | 低（スコープ・期限付きキー） | 中（実験的） |
| 内部API + Cookie | △ | ほぼ0 | 高 | 中 |
| Playwright で画面操作 | ○ | ほぼ0 | 中 | 高 |
| LLM にブラウザ操作 | △ | 高 | 中〜高 | 結果が毎回同じとは限らない |
| 拡張機能 | △ | ほぼ0 | 最低 | 中 |

方針は次のとおり。
1. 投稿は **公式 Public API（zenn-cli）** を使い、足りない部分だけ薄いラッパーを書く。
2. **LLM は Markdown を書くところまで**。投稿は決定的に動く CLI に任せる。
3. リポジトリを正とする。`scraps/<topic>/meta.yml` と `NNN.md`（1ファイル = 1コメント）で管理し、投稿後に slug と hash を書き戻す。
4. 安全装置として、dry-run、1日N件の上限、429 で即停止、POST は再試行しない、最初は `unlisted` で試す、を入れる。
5. 投稿後は GET で取得して、ローカルの内容と照合する。

このスクラップ自体も、この仕組みで投稿する予定（ドッグフーディング）。
