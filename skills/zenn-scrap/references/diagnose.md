# 止まったとき・照合で NG が出たとき

まず**何も送り直さない**。POST は再試行しない作りで、送り直すと二重投稿になりうる。

relay で止まったときは、どの表示でも次の順にする。まとめて送る手(`--count 4`)は1件ずつ照合して送るので、止まる前の分はもう投稿されていることがある。

1. 返った JSON を**そのまま** `zs record <topic> @<一時フォルダ>/result.json` で書き戻す(一時フォルダは [post.md](post.md) の 1)。送れた分(`comment_slug` があるもの)だけが記録される。JSON が手元にないときは、同じタブで `sessionStorage.getItem("zenn-scrap:last")` を見る。タブも閉じていたら、下の表の `HTTP 5xx` の行のとおり画面で確かめる
2. 原因を下の表で直す
3. `zs relay` で `step.js` を**作り直す**。記録済みの分は外れ、まだ送っていない最初の件から始まる。同じ `step.js` を流し直さない(送れた分が二重になる)
4. 作り直した `step.js` を送るのは、ユーザーの指示があってから

症状を下の表で探し、分からなければ、表示されたメッセージをそのままユーザーに見せて相談する。

`zs` は `uv run --project <原稿リポジトリ>/tools/scrap zenn-scrap` の略。

## dry-run(`zs post`)で止まる

| 表示 | 原因と対応 |
| --- | --- |
| `x NNN.md: 〜らしき文字列がある` | 秘密情報の検査に引っかかった。本物なら消す。例示のつもりなら `...` などに伏せる |
| `x 〜 文字を超える` | title は 100 文字、本文は 20,000 文字まで。分けるか縮める |
| `保留(今日の上限)` | 1日の上限(既定 20)。翌日に回す。上限を上げて押し通さない |
| `! 投稿後に変更されている` | 投稿済みのファイルが変わった。`git checkout -- <ファイル>` で戻す。訂正は次の番号で |

## relay(JavaScript の結果)で止まる

| 表示 | 原因と対応 |
| --- | --- |
| `ログインしていない` | その Chrome で Zenn からログアウトしている。ログインは送信の前に確かめるので、この手では何も送っていない。ユーザーにログインしてもらってから続ける |
| `sha256 が一致しない` | JavaScript を渡すときに本文が変わった(打ち直した、一部を省いた など)。原稿ファイルの問題ではない。その件は送られていないが、前の件は送られていることがある。上の 1〜3 のとおりにし、作り直した `step.js` を Read で読んで、中身を一字も変えずに渡す |
| `zenn.dev のタブで実行していない` | `navigate` で `https://zenn.dev/` を開いてから実行する |
| `Identifier 'job' has already been declared` など | 同じページで2回実行した。開き直してから実行する |
| `POST 〜 が失敗した` + `HTTP 401` | ログイン切れ。ログインし直す |
| 同 `HTTP 403` | 権限がない(他人のスクラップ、アーカイブ済み、コメント数の上限など)。`detail` を見る |
| 同 `HTTP 404` | スクラップが消えた、または slug が違う。zenn.dev で確かめる |
| 同 `HTTP 422` | 入力の問題。`detail` を見て原稿を直す |
| 同 `HTTP 429` | 投稿数かリクエスト数の上限。**その日は終える**。間隔を変えて回避しようとしない |
| 同 `HTTP 5xx`、または応答がない | 送れたかどうか分からない。zenn.dev でスクラップを開き、コメントが増えたかを目で確かめる。増えていたら、その slug で `record` 用の JSON を手で作ってユーザーに確認してから書き戻す |
| ツールが `Browser extension is not connected` など | 拡張機能との接続が切れた。ユーザーに `/chrome` →「Reconnect extension」をしてもらう |

## `record` で止まる

| 表示 | 原因と対応 |
| --- | --- |
| `sha256 が手元のファイルと違う` | `relay` のあとにファイルが変わった。ファイルを戻すか、`relay` からやり直す |
| `すでに投稿済みとして記録されている` | 同じ結果を2回書き戻そうとした。`meta.yml` を見て、記録済みなら何もしない |

## `verify` で NG が出る

| 表示 | 原因と対応 |
| --- | --- |
| `can_others_post が違う` / `topics が違う` / `title が違う` | 設定が Zenn に反映されていない。`meta.yml` の `settings_sha256:` の行を消してから `zs relay <topic>` を実行すると、設定を送り直す1手が出る |
| `unlisted が違う` | ユーザーが画面で公開に切り替えた(限定公開には戻せない)。ユーザーに確かめ、意図どおりなら `meta.yml` の `unlisted` を合わせる |
| `コメントの slug が違う` | Zenn 側でコメントが消された、または `record` し忘れた。zenn.dev で確かめる |
| Markdown の照合(`relay-verify`)で `ng` | Zenn 上の本文が送ったものと違う。画面で編集されたか、送信で崩れた。ユーザーに見せて相談する |

## 内部 API が変わったらしいとき

それまで動いていた呼び出しが、4xx や想定外の応答になる。Zenn の内部 API は予告なく変わりうる(利用規約第18条)。

1. 送るのをやめる
2. 現在の呼び方を、zenn.dev のフロントエンドの JS から読む(読むだけで、送らない)
   - `https://zenn.dev/` の HTML から `_buildManifest.js` の URL を探し、`/scraps/new` と `/[username]/scraps/[slug]` のチャンクを取る
   - チャンクの中で `post("/scraps"`、`post("/comments"`、`put(\`/scraps/` を探す。クライアントは JSON のキーを snake_case にして送っている
3. 分かったことを、調査メモ(`zenn_scraps_automate/docs/research/02`)と、スクラップのコメント([log.md](log.md) の形)に残す
4. ツールの原本を直し、テストを通してから、原稿リポジトリへコピーし直す

## Public API が使えるようになったか

設定画面に「APIキー」タブが出ていれば、使えるようになっている。zenn.dev のタブで `(await (await fetch("/api/me")).json()).current_user.public_api_enabled` が `true` になっていても同じ。
使えるなら、キーを発行して(スコープは `scrap:read` と `scrap:write:own`)環境変数 `ZENN_API_KEY` に置き、`zs post <topic> --execute --transport public-api` に切り替えられる。最初は限定公開のスクラップで1件だけ試す。
