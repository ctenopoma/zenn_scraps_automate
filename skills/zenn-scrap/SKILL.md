# zenn-scrap — 調査・試行を逐次スクラップに記録する

調べたこと・試したことを、**まとまりごとに1コメント**ずつ Zenn のスクラップへ記録する。
区切りごとに、チャットには要約と結論を、スクラップには根拠や出典まで含めた詳細を残す。最後に長文をまとめて出すより、読む側が追いやすいため。

原稿は Zenn の GitHub 連携リポジトリの `scraps/<topic>/`(`meta.yml` と `001.md`, `002.md` …)。
投稿と照合は CLI(`tools/scrap/` の zenn-scrap)が行う。LLM の担当は原稿を書くところまで。

## 最初に

このスキルのフォルダの `local.md` を読む。原稿リポジトリの場所が書いてある。送るのは relay(普段の Chrome)だけ。
`local.md` がなければ、まだ導入していない。[references/install.md](references/install.md) に進む。

以下、`zs` は `uv run --project <原稿リポジトリ>/tools/scrap zenn-scrap` の略。

## やりたいこと → 読むファイル

必要になったものだけを読む。全部を先に読まない。

| やりたいこと | 読むファイル |
| --- | --- |
| ツールを導入したい、前提条件を確かめたい | [references/install.md](references/install.md) |
| 調べたこと・試したことを記録したい(新しいスクラップを始める、追記する) | [references/log.md](references/log.md) |
| 書いた原稿を送りたい(投稿、照合、コミット) | [references/post.md](references/post.md) |
| 止まった、照合で NG が出た、動かない | [references/diagnose.md](references/diagnose.md) |

## 共通ルール(どの作業でも守る)

- **送るのはユーザーが指示したときだけ。** 「記録して」「載せて」と言われたテーマは、そのセッション中は区切りごとに送ってよい。言われていないテーマの原稿は、書いても送らずに確認する。「送ればいい？」のような質問は指示ではないので、答えたうえで確認を取る。Zenn は「ボットによるアカウントの自動運用」を懸念しているため、人が指示する形を崩さない
- **投稿済みの `NNN.md` は直さない。** 再投稿はされず、照合で不一致になる。訂正は次の番号のコメントで「訂正:」と書く
- **秘密を書かない。** API キー、Cookie、社内の URL、顧客の情報。限定公開でも URL を知る人は読める。CLI も送信前に検査する
- **上限を探らない。** 1日 20 コメントまで(ツールの既定)。Zenn の上限の基準は非公開で、上限に当てて挙動を調べる投稿はしない。止まったら再試行せず、[references/diagnose.md](references/diagnose.md) を読む
- **事実と推測を分ける。** 事実には出典(URL、実行したコマンドと結果)を付け、推測には「(推測)」と書く
